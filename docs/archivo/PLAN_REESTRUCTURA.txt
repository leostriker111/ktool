 PROPOSITO / METADATOS
 ---------------------
 Por que se creo: el repo crecio "regado" (paquete plano de 13 modulos, gui.py de
   851 lineas) y, antes de meter las maquinas de estado y mas displays, se decidio
   reordenar a subpaquetes (core/render/gui) y de paso reemplazar el traductor de
   lenguajes hardcodeado (dict SPECS) por un mini-compilador lexer->parser->AST->codegen.
 Creado en: v0.3.0  (2026-06-09)
 Aplicado/usado en: v0.4.0  (PENDIENTE: marcar la fecha real al ejecutar la Etapa C)
 Estado: PROPUESTA - aun NO ejecutado.

Este documento es la guia para reorganizar el paquete y reemplazar el traductor
de lenguajes (hoy hardcodeado en un dict SPECS) por un mini-compilador limpio:
lexer -> parser -> AST -> codegen. Pensado para ejecutarse por etapas; si una
sesion se queda sin tokens, otra puede retomar siguiendo el orden de la seccion 6.

Principio rector (palabras del autor): "diseña bien, construye poco; diseña mal,
construye mucho". Por eso el traductor entra AHORA, antes de que haya mil cosas
encima.

--------------------------------------------------------------------------------
 4. EL TRADUCTOR: lexer -> parser -> AST -> codegen  (Etapa B)
--------------------------------------------------------------------------------
OBJETIVO: quitar el dict SPECS (templates hardcodeados) y traducir SOBRE el AST,
con precedencia y parentesis correctos. Beneficio doble:
  (a) se puede traducir CUALQUIER expresion que el usuario escriba (matematico ->
      Verilog/VHDL/ABEL/Logisim/C/Python/LaTeX), no solo el resultado minimizado.
  (b) los resultados minimizados (Solution) se convierten a AST y pasan por el
      MISMO emisor -> una sola fuente de verdad, sin duplicar la logica de unir
      literales.

render/codegen.py contiene:
  - LANG_ORDER = [...]                     (igual que hoy)
  - OPS = { por lenguaje: simbolos de and/or/not/xor, repr de const, repr de var
            (normal y complementada), plantilla de asignacion, parentesis }.
            Es DATOS, no logica; agregar lenguaje = agregar una entrada.
  - def emit(node, lang) -> str            EMISOR recursivo sobre el AST con
            parentizacion por precedencia (NOT > AND > XOR > OR). El parentesis se
            decide comparando precedencia del nodo hijo vs el padre; NO va
            hardcodeado por caso.
  - def solution_to_ast(solution) -> AST   SOP = or(and(literales)); POS =
            and(or(literales invertidos)); XOR = cadena xor(vars) [+ not si xnor];
            const -> ('const', v).
  - def render(solution, name, lang) -> str        = assign(name, emit(solution_to_ast(solution), lang))
  - def render_all(solution, name) -> [(lang, codigo)]
  - def translate(expr_text, name, lang) -> str    NUEVO: parse(expr_text) -> emit
            (esto es el "traductor matematico -> lenguaje" para texto libre)

SEAM / COSTURA PLY-SLY (a futuro, opcional):
  El unico contrato es el AST (tuplas de ast.py). Si algun dia se quiere meter
  PLY o SLY como ejercicio, se reemplaza SOLO core/lexer.py + core/parser.py por
  una version PLY que produzca el MISMO AST, y codegen/simplify/todo lo demas no
  se entera. Por eso hoy se queda el lexer+parser propios (cero dependencias,
  mas profesional para una gramatica chica, y demuestra las bases hechas a mano).

EXPONER EN CLI/GUI (opcional, mismo Etapa B o despues):
  - CLI: `kmap -e "A'B+C" --to verilog`   -> imprime la traduccion directa.
  - GUI: campo "traducir a:" junto a la barra de expresion.
